# 子午花信小程序 UI 交互规范

## 1. 交互原则

子午花信的交互应服务于长期日常使用，强调稳定、克制、明确和可恢复。

交互原则：

- 用户每次点击都应有即时反馈。
- 高风险操作必须二次确认。
- 打卡、取消、保存、删除等核心操作必须让用户知道结果。
- 网络异常时优先保留本地操作，再提示稍后同步。
- 空状态、加载状态、错误状态必须可识别，不展示无说明空白页。
- 页面切换与弹窗动效应轻量，避免干扰养生打卡的安静气质。

## 2. 信息架构与页面入口

一级导航采用四个 Tab：

| Tab | 页面 | 功能定位 |
|---|---|---|
| 案台 | 首页 | 今日时辰、今日修习、打卡入口 |
| 修习 | 习惯管理 | 添加、编辑、删除修习习惯 |
| 观心 | 数据报表 | 查看周、月、年修习数据 |
| 归藏 | 个人中心 | 用户信息、偏好设置、关于信息 |

入口规则：

- 案台页是每日打卡默认入口。
- 首页无修习时，添加入口进入修习页。
- 修习页管理习惯和策略。
- 观心页只负责数据查看，不承载编辑习惯流程。
- 归藏页承载个人资料和设置入口。

## 3. 自定义底部导航交互规范

小程序一级导航使用自定义底部 TabBar。

实现口径：

- 自定义 TabBar 是唯一一级导航交互来源。
- `app.json` 中的原生 TabBar 配置仅用于小程序路由声明和微信能力兜底。
- `components/tab-bar`、`components/nav-bar`、`components/navigation-bar` 若未被当前一级页面引用，不作为页面导航交互来源。
- 不以 `app.json` 的原生 `selectedColor`、`backgroundColor` 判断当前 UI 是否合格。
- 页面进入或显示时必须同步 `custom-tab-bar` 的 selected 状态。

交互要求：

- 点击 Tab 使用 `wx.switchTab`。
- 点击当前 Tab 不重复跳转。
- 页面进入时同步当前 selected 状态。
- 页面内部不得重复实现底部导航。
- 页面内容底部必须预留安全空间，避免被 TabBar 遮挡。

状态要求：

| 状态 | 表现 |
|---|---|
| 默认态 | 默认图标、弱文字 |
| 选中态 | active 图标、主色文字 |
| 点击当前 Tab | 不跳转、不闪烁 |
| 切换 Tab | 立即切换页面并更新选中态 |

## 4. 案台页交互规范

### 4.1 页面进入

页面进入时应完成：

- 读取今日应修习惯。
- 计算当前时辰、经络和养生建议。
- 计算今日完成数、总数和进度百分比。
- 同步底部 TabBar 选中态为“案台”。

### 4.2 打卡前状态

未打卡习惯应展示：

- 习惯图标。
- 习惯名称。
- 待完成说明或习惯 meta。
- 默认图标容器。

### 4.3 点击打卡

用户点击习惯项后：

1. 立即触发按压反馈。
2. 检查是否正在处理同一习惯，若是则忽略重复点击。
3. 本地立即切换完成状态。
4. 更新累计天数。
5. 更新今日完成数和进度条。
6. 调用 `checkinService` 生成打卡操作、更新每日最终状态并进入必要的 pending 同步。
7. 由 `syncService` 通过 `cloudService` 尝试同步云端。
8. 展示成功或本地保存提示。

防抖规则：

- 同一习惯 1 秒内重复点击应被忽略。
- 防抖不影响其他习惯的点击。

### 4.4 已打卡状态

已打卡习惯应展示：

- 完成标识。
- 累计天数。
- 今日进度同步增加。
- 报表数据最终一致。

### 4.5 取消打卡

用户再次点击已打卡习惯：

1. 本地立即回退完成状态。
2. 累计天数减少，但不得低于 0。
3. 更新今日进度。
4. 调用 `checkinService` 生成取消操作，并更新 `dailyCheckinState`。
5. 由 `syncService` 处理取消操作的 pending 与云端同步。
6. 展示取消成功或稍后同步提示。

### 4.6 网络异常

网络异常时：

- 本地状态保持用户刚刚操作的结果。
- Toast 提示已保存本地，网络恢复后同步。
- 不回滚用户刚刚完成的操作。
- 可在后续版本增加“待同步”弱状态。

### 4.7 跨天刷新

跨天后：

- 页面重新进入或重新显示时刷新今日任务。
- 今日打卡状态按新日期重新计算。
- 历史打卡不得影响新日期默认状态。

## 5. 修习页交互规范

### 5.1 页面进入

页面进入时应完成：

- 读取全部习惯和用户已添加习惯。
- 合并默认习惯与用户策略。
- 过滤已删除习惯。
- 同步底部 TabBar 选中态为“修习”。
- 默认展示当前分类下的习惯列表。

### 5.2 分类切换

顶部分类 Tab：

- 点击分类后立即更新选中态。
- 列表切换到对应分类。
- 分类为空时展示空状态。
- 不跳转页面。

### 5.3 创建习惯策略

点击未添加习惯：

1. 打开策略设置底部弹窗。
2. 载入习惯名称、默认时长和默认频率。
3. 默认频率为每日。
4. 默认计划开始时间为今天。
5. 用户保存后调用 `habitService` 创建用户习惯实例和首个策略版本。
6. 由 `syncService` 通过 `cloudService` 尝试同步云端。
7. 关闭弹窗并刷新列表。
8. Toast 提示保存成功。

### 5.4 编辑习惯策略

点击已添加习惯：

1. 先展示操作菜单。
2. 用户选择“修改策略”后打开策略弹窗。
3. 弹窗中回填已保存策略。
4. 用户修改后保存。
5. 调用 `habitService` 生成新策略版本，并由 `syncService` 同步云端。
6. 刷新修习页、首页和报表相关数据。

长按已添加习惯：

- 可直接进入编辑策略弹窗。
- 未添加习惯长按只提示“单击添加习惯”。

### 5.5 删除习惯

删除入口：

- 已添加习惯点击后进入操作菜单。
- 选择删除后必须展示二次确认。

确认弹窗要求：

- 标题明确为删除习惯。
- 文案说明删除对象。
- 文案说明历史打卡数据是否保留。
- 确认按钮使用危险色。
- 若使用系统 `wx.showModal`，`confirmColor` 统一为 `#F0655B`。
- 不使用微信默认红 `#e64340` 作为子午花信危险色。
- 取消按钮关闭确认弹窗，不做任何变更。

操作菜单要求：

- 删除入口对应的菜单项必须带 `type: danger`。
- WXML/CSS 必须根据 `item.type` 渲染危险色。
- 删除菜单项不得显示为品牌主色，避免和普通编辑操作混淆。

删除成功后：

- 从我的修习中移除该习惯。
- 保留历史打卡记录。
- 刷新修习页列表。
- 首页今日任务同步移除。
- 报表保留历史数据并标记删除状态。
- Toast 提示移除成功。

### 5.6 空习惯状态

分类无数据时：

- 展示空状态说明。
- 若为全部或初始化场景，可展示初始化/添加入口。
- 空状态不得只显示空白。

## 6. 策略表单交互规范

策略表单字段：

- 单次目标。
- 每天。
- 每周。
- 间隔天数。
- 计划开始时间。

字段交互：

- 点击单次目标打开时长选择器。
- 点击每周打开星期选择器。
- 点击间隔天数打开天数选择器。
- 点击自定义日期打开日期选择器。
- 选择完成后回填字段值。
- 未保存前仅更新弹窗内状态。
- 点击保存后才写入策略。

校验规则：

- 单次目标必须有值。
- 每周至少选择一天。
- 间隔天数必须大于 0。
- 计划开始时间不得早于允许的最小日期。
- 校验失败优先在字段附近提示，必要时使用 Toast。

## 7. 选择器交互规范

### 7.1 PickerSheet 通用交互

所有选择器使用底部弹窗：

- 点击字段打开。
- 点击蒙层关闭。
- 点击关闭按钮关闭。
- 滚动选择时不立即保存到策略。
- 点击确认后回填当前字段。
- 关闭不确认时保留原字段值。

### 7.2 时长选择器

交互规则：

- 打开后定位到当前已选时长。
- 滚动选择分钟数。
- 点击确认后更新单次目标。
- 文案格式为 `{分钟数} 分钟`。

### 7.3 天数选择器

交互规则：

- 打开后定位到当前间隔天数。
- 滚动选择天数。
- 点击确认后更新间隔天数。
- 文案格式为 `{天数} 天`。

### 7.4 星期选择器

交互规则：

- 打开后回显已选星期。
- 点击星期项切换选中/未选。
- 允许多选。
- 点击确认前不关闭弹窗。
- 点击确认后回填星期文案。
- 未选择星期时确认应提示错误。

### 7.5 日期选择器

交互规则：

- 打开后定位到当前计划开始日期。
- 年、月、日三列联动。
- 月份变化后需校正日期范围。
- 选择日期不得早于最小可选日期。
- 点击确认后回填日期。
- 不合法日期 Toast 提示并停留在选择器。

## 8. 观心页交互规范

### 8.1 页面进入

页面进入时应完成：

- 读取用户习惯和打卡记录。
- 若本地为空，可尝试恢复云端数据。
- 默认展示周报。
- 计算当前周期标题和农历/日期副标题。
- 同步底部 TabBar 选中态为“观心”。

### 8.2 报表类型切换

报表类型：

- 周报。
- 月报。
- 年报。

切换规则：

- 点击 Tab 后立即更新选中态。
- 更新日期标题和副标题。
- 加载对应报表数据。
- 非当前报表内容隐藏。
- 切换失败时展示错误状态。

### 8.3 时间周期切换

观心页时间选择器指报表页顶部日期周期切换控件。

交互规则：

| 当前报表 | 左箭头 | 右箭头 |
|---|---|---|
| 周报 | 前一周 | 后一周 |
| 月报 | 前一月 | 后一月 |
| 年报 | 前一年 | 后一年 |

切换后：

- 更新周期状态。
- 更新日期标题。
- 更新日期副标题。
- 重新加载数据。
- 保持当前报表类型不变。

### 8.4 周报交互

周报展示：

- 每个习惯一行。
- 左侧习惯图标和名称。
- 右侧 7 天点阵。
- 下方统计看板。

状态规则：

- 已完成：主题色填充。
- 未完成：白底 + 主题色描边。
- 非应修日：浅灰底。
- 删除后日期：浅灰底。
- 删除前历史完成：保留主题色。

### 8.5 月报交互

月报展示：

- 每个习惯一张月历卡。
- 月历按 7 列展示。
- 每日状态跟随习惯主题色。
- 卡片底部显示完成率和完成天数。

交互要求：

- 无需点击单日进入详情。
- 日期状态必须与打卡记录一致。
- 未来日期使用浅灰状态。

### 8.6 年报交互

年报展示：

- 每个习惯一张年热力图。
- 热力图按 53 列 x 7 行展示。
- 完成强度用主题色透明度表达。

强度规则：

- level-1：`opacity: 0.3`
- level-2：`opacity: 0.6`
- level-3：`opacity: 0.9`

## 9. 归藏页交互规范

### 9.1 页面进入

页面进入时应：

- 读取用户头像。
- 读取用户昵称。
- 同步底部 TabBar 选中态为“归藏”。

### 9.2 头像选择

交互规则：

- 点击头像触发微信头像选择能力。
- 选择后立即本地预览。
- 上传中展示 Loading。
- 上传成功后保存头像地址。
- 上传失败保留本地预览或回退，并 Toast 提示。

### 9.3 昵称编辑

交互规则：

- 昵称输入框支持微信昵称能力。
- 输入失焦后保存。
- 昵称为空时使用默认昵称或 placeholder。
- 保存失败 Toast 提示。

### 9.4 设置项

设置项点击后：

- 已实现功能进入对应页面或弹窗。
- 未开放功能使用 Toast 说明。
- 不得表现为已完成流程。

## 10. 弹窗与反馈交互规范

### 10.1 BottomSheet

使用场景：

- 策略设置。
- 操作菜单。
- 选择器。

交互规则：

- 从底部上滑出现。
- 蒙层淡入。
- 点击蒙层可关闭普通弹窗。
- 点击关闭按钮可关闭。
- 保存或确认成功后关闭。
- 关闭时不保存未确认内容。

### 10.2 ConfirmDialog

使用场景：

- 删除习惯。
- 清空数据。
- 其他不可逆或高风险操作。

交互规则：

- 必须明确标题。
- 必须说明影响。
- 必须有取消和确认。
- 取消不产生副作用。
- 确认后执行操作并给出结果反馈。

### 10.3 Toast

使用场景：

- 打卡成功。
- 取消打卡。
- 保存成功。
- 删除成功。
- 网络异常。
- 功能未开放。
- 校验失败。

文案要求：

- 简短明确。
- 一次只表达一个结果。
- 网络异常需说明是否已本地保存。

### 10.4 Loading

使用场景：

- 数据恢复中。
- 头像上传中。
- 长耗时保存中。

交互要求：

- Loading 期间避免重复提交。
- 成功或失败后必须关闭 Loading。
- 失败后必须给出 Toast 或 ErrorState。

## 11. 异常状态交互规范

| 场景 | 表现 | 用户操作 |
|---|---|---|
| 无修习 | EmptyState + 添加入口 | 去修习页添加 |
| 无报表数据 | EmptyState + 说明 | 返回案台或修习 |
| 加载中 | LoadingState | 等待 |
| 网络异常 | Toast，本地保存 | 稍后自动同步 |
| 数据恢复中 | LoadingState | 等待 |
| 数据恢复失败 | ErrorState + 重试按钮 | 点击重试 |
| 字段缺失 | 默认文案、默认图标、默认主题 | 无需用户处理 |
| 删除失败 | Toast 或 ErrorState | 重试或稍后操作 |

异常文案要求：

- 不暴露技术错误堆栈。
- 告诉用户当前结果。
- 告诉用户是否需要操作。
- 可恢复错误必须提供重试入口。

## 12. 动效与点击态规范

| 场景 | 动效 |
|---|---|
| 普通点击 | opacity 或 scale 轻反馈 |
| 主按钮点击 | `scale(0.96)` |
| 首页习惯点击 | `translate3d(0, 2rpx, 0) scale(0.94)` |
| 底部弹窗出现 | `translateY(100%)` 到 `translateY(0)` |
| 蒙层出现 | opacity `0` 到 `1` |
| 进度条变化 | width 变化，约 `520ms` |
| Tab 文字切换 | color `300ms ease` |

动效要求：

- 只动画 `transform`、`opacity`、`color`、`width`。
- 不动画 layout 大幅变化。
- 不使用过度弹跳。
- 不使用长时间循环动效。
- 所有反馈应克制，不破坏安静养生气质。

## 13. 数据一致性交互规范

数据同步关系：

- 首页打卡状态来自今日习惯和打卡记录。
- 修习页策略变化会影响首页今日任务。
- 修习页删除会影响首页今日任务。
- 观心页报表来自习惯策略和打卡记录。
- 删除习惯后，报表保留删除前历史数据。

一致性要求：

- 打卡后首页进度立即更新。
- 打卡后观心页最终展示一致。
- 创建策略后首页出现对应今日任务。
- 删除习惯后首页不再展示今日任务。
- 删除习惯后报表保留历史数据。
- 本地缓存恢复后四个主页面数据状态一致。

## 14. 交互验收清单

- [ ] 点击底部 Tab 是否正确切换页面
- [ ] 底部导航验收是否以 `custom-tab-bar` 为准
- [ ] 点击当前 Tab 是否不重复跳转
- [ ] 首页打卡是否即时更新状态
- [ ] 首页打卡是否更新今日进度
- [ ] 首页重复点击是否防抖
- [ ] 已打卡习惯是否支持取消打卡
- [ ] 网络异常时是否保留本地操作
- [ ] 跨天后首页状态是否刷新
- [ ] 修习页分类切换是否正确
- [ ] 点击未添加习惯是否打开创建策略弹窗
- [ ] 点击已添加习惯是否出现操作菜单
- [ ] 删除操作菜单项是否按 `type: danger` 显示危险色
- [ ] 长按已添加习惯是否进入编辑
- [ ] 删除习惯是否二次确认
- [ ] 删除确认按钮颜色是否使用 `#F0655B`
- [ ] 删除后首页、修习页、观心页是否一致
- [ ] 时长选择器确认后是否回填字段

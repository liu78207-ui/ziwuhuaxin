# 子午花信小程序 UI 视觉规范

## 0. 规范适用范围与实现口径

本文是产品开发、组件重构与 UI 验收的视觉基准。页面实现以小程序实际使用的全局样式、页面样式和自定义组件为准，不以 `app.json` 中原生 TabBar 的颜色配置作为视觉验收依据。

实现口径：

- 小程序使用 `navigationStyle: custom`，顶部标题由页面自行绘制。
- 一级底部导航以 `custom-tab-bar` 为唯一视觉来源。
- `components/tab-bar`、`components/nav-bar`、`components/navigation-bar` 若未被当前一级页面引用，不作为验收基准。
- `app.json` 中 TabBar 的 `selectedColor`、`backgroundColor` 仅作为微信配置兜底，不进入视觉规范 token。
- 页面背景以 `app.wxss` 的 `--bg-body / --color-bg-page` 为准。
- 全局字体族统一使用系统字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Helvetica Neue", Arial, sans-serif`。
- `.paper-grain`、`.glass-card`、`.card`、`.card-container` 属于全局视觉工具类，必须按场景使用，不得作为页面临时装饰滥用。

## 1. 设计定位

子午花信是一款东方养生习惯打卡小程序，视觉体验服务于“日常修习、时辰养生、习惯坚持、数据观照”。

整体气质：

- 东方养生
- 温润安静
- 轻盈自然
- 秩序清晰
- 女性友好
- 日常可长期使用
- 反馈明确但克制

视觉边界：

- 不使用强运营感视觉。
- 不堆砌传统纹样。
- 不使用高饱和撞色。
- 不制造厚重阴影。
- 不使用过度动效和持续闪烁。

### 2.3 主题 CSS 变量机制

主题类挂载在习惯项、卡片、报表行或日历容器上，通过 CSS 变量向内部元素传递主题色。

统一变量：

```css
--theme-color
--theme-bg
--icon-shadow
```

变量规则：

| Class | `--theme-color` | `--theme-bg` | `--icon-shadow` |
|---|---:|---:|---|
| `.t-green` | `#38A385` | `#E2F2ED` | `0 8px 20px rgba(56, 163, 133, 0.08)` |
| `.t-red` | `#F0655B` | `#FDE8E7` | `0 8px 20px rgba(240, 101, 91, 0.08)` |
| `.t-yellow` | `#F2A93B` | `#FEF3E1` | `0 8px 20px rgba(242, 169, 59, 0.08)` |
| `.t-blue` | `#5A8CB6` | `#E7F0F6` | `0 8px 20px rgba(90, 140, 182, 0.08)` |
| `.t-purple` | `#9D7BB0` | `#F3EBF6` | `0 8px 20px rgba(157, 123, 176, 0.08)` |

使用要求：

- 习惯组件外层必须带 `themeClass`。
- 内部图标底色使用 `var(--theme-bg)`。
- 完成态、描边、热力图色块使用 `var(--theme-color)`。
- 主题图标阴影使用 `var(--icon-shadow)`，仅用于需要强调的图标容器。
- 主题色不得在页面内重新硬编码。
- 新增习惯必须先进入主题映射表，再进入页面展示。

### 2.5 主题 fallback 规则

新增或未知习惯按以下顺序获取主题：

1. 按习惯名称匹配主题映射表。
2. 名称未命中时按分类兜底：
   - 运动类：`t-green`
   - 理疗类：`t-red`
   - 起居类：`t-yellow`
3. 分类仍无法命中时，兜底为 `t-blue`。

### 2.6 非主题装饰色与旧色处理

五主题色是习惯系统、报表系统和主要状态的唯一主题来源。页面内若存在时辰卡片装饰、历史视觉残留或一次性硬编码色，必须按以下规则处理：

| 色值 | 归属 | 允许场景 | 处理规则 |
|---|---|---|---|
| `#C4786A` | 时辰卡片装饰暖红 | 案台页时辰卡片背景弱光、不可作为按钮或状态色 | 建议 token 化为 `--color-time-deco-rose` |
| `#8B9A7C` | 时辰卡片装饰草木灰绿 | 案台页时辰卡片背景弱光、不可替代 `t-green` | 建议 token 化为 `--color-time-deco-sage` |
| `#D4A574` | 时辰卡片装饰暖金 | 案台页时辰卡片背景弱光、少量统计装饰 | 建议 token 化为 `--color-time-deco-gold` |
| `#F5E6E0`、`#E8E4D9`、`#D4E5E0`、`#E5DED4`、`#D9E2E8`、`#E8D9D9` | 旧九宫格浅底色 | 不再作为新增习惯视觉规范 | 新增页面不得继续扩散，需映射到五主题浅底 |
| `#e64340` | 微信默认危险红 | 不作为子午花信视觉规范色 | 删除、清空等危险操作统一使用 `--color-danger` |

要求：

- 新增样式不得继续引入未命名硬编码色。
- 若装饰色确有保留价值，必须进入 token，并限定使用场景。
- 旧色不得与五主题色混合作为习惯主题。

| `--radius-sheet` | `40rpx 40rpx 0 0` | Picker、ActionSheet 底部弹窗 |
| `--radius-pill` | `999rpx` | 主按钮、标签、Tab 指示条 |

### 5.2 圆角包裹规则

- 外层容器圆角必须大于内层元素圆角。
- 卡片 `32rpx` 圆角内的图标底建议使用 `24rpx`。
- 弹窗顶部使用大圆角，内部表单分组使用 `24rpx`。
- 圆形按钮只能用于明确的 icon 操作，不用于长文本。
- 胶囊按钮仅用于主按钮、标签和短选项，不用于大面积卡片。
- 日历格和热力图圆角必须小于卡片圆角，避免格子抢占容器层级。

| Token | 值 | 使用场景 |

- 不使用纯黑边框。

| Token | 值 | 使用场景 |

- 不使用持续闪烁的外发光。

- 不新增 `99999` 类逃逸层级。

- 蒙层出现时底部 TabBar 不应抢占视觉焦点。

## 7. 图标与插画规范

图标要求：

- 习惯图标使用 PNG 资产。
- 图标必须与习惯名称、主题色保持一致。
- 不将 emoji 作为正式图标体系，只作为 fallback。

- 图标尺寸按场景统一。

## 12. 样式架构规范

建议文件：

- `design-tokens.wxss`：颜色、字号、间距、圆角、阴影、层级。
- `theme.wxss`：五主题色、主题 class、主题变量。
- `common.wxss`：页面容器、标题、卡片、按钮、空状态等公共样式。
- `components.wxss`：基础组件类，如按钮、弹窗、选择器、卡片。

建议组件：

- `BaseButton`
- `BaseCard`
- `BaseTag`
- `PageHeader`
- `TopTabs`
- `DatePeriodControl`
- `EmptyState`
- `LoadingState`
- `ErrorState`
- `ConfirmDialog`
- `BottomSheet`
- `PickerSheet`
- `ActionSheet`
- `HabitIcon`
- `ReportStatusCell`

开发要求：

- 新页面必须使用全局 token。
- 新习惯必须配置图标和主题色。
- 不允许在页面内硬编码主题色。
- 不允许重复实现底部导航。
- 不允许页面样式污染基础组件。
- 同类弹窗、按钮、卡片必须复用基础组件。
- 所有新增浮层必须进入统一层级体系。
- 所有新增 picker 必须使用统一 PickerSheet 容器。

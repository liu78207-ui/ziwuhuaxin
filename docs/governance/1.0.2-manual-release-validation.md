# 1.0.2 云同步恢复手工验收指南

本文档用于验证 1.0.2 的环境隔离、全量分页恢复、完整快照校验、缓存安全替换以及核心功能回归。

读者不需要会写代码。请严格按顺序操作，并为每个场景保存截图。任何一步与“预期结果”不一致时立即停止，不要提交审核、不要发布，也不要手工修改正式数据库。

## 一、先理解两个重要限制

### 1. 体验版不能验证正式数据

- 开发版、体验版显示“测试环境”，只使用 `test_` 开头的测试集合。
- 正式版不显示“测试环境”，只使用无前缀的正式集合。
- 因此，体验版看不到正式版历史是正确结果，不是数据丢失。

### 2. 新客户端的正式环境恢复只能在正式发布后最终确认

微信体验版运行的是 `trial` 环境，按照本项目的安全规则必须连接测试集合。它不能临时切换到正式集合。

所以：

- 发布前：在体验版完成测试环境的全部验证；在腾讯云控制台确认正式恢复云函数配置正确；用当前正式版确认正式云端数据仍存在。
- 发布后：先用自己的正式账号验证 1.0.2 正式版，再逐步扩大用户范围。

不要为了“发布前测试正式数据”而让体验版连接正式集合，这会破坏环境隔离。

## 二、验收前准备

准备以下内容：

1. 一部安装微信的手机。
2. 两个真实微信账号：
   - 账号 A：自己的正式数据账号。
   - 账号 B：测试账号，可以接受测试数据被清理。
3. 微信公众平台管理员权限。
4. 腾讯云 CloudBase 控制台权限。
5. 体验版二维码，版本号必须是 `1.0.2`。
6. 本文档最后的验收记录表。

安全要求：

- 只使用小程序内“归藏 → 清空缓存”。
- 不要在微信系统设置中删除小程序数据。
- 正式数据库只查询和截图，不新增、不编辑、不删除记录。
- 每次点击“清空缓存”前，先确认当前是体验版还是正式版。
- 体验版必须看到“测试环境”标识；正式版必须看不到这个标识。

## 三、执行顺序

请按以下顺序执行：

1. 场景 1：确认两个恢复云函数的环境边界。
2. 场景 3：体验版清缓存恢复与环境隔离。
3. 场景 4：体验版核心功能回归。
4. 场景 5：体验版断网恢复失败保护。
5. 场景 2：1.0.2 正式发布后，用自己的正式账号最终确认。
6. 场景 4：1.0.2 正式版核心功能回归。
7. 场景 6：1.0.2 正式版大数据账号恢复耗时和完整性。

场景 2、场景 4 的正式版部分和场景 6 的正式版部分，在正式发布前不能执行。当前正式版 1.0.0 禁止用于清缓存恢复验收。

## 场景 1：确认正式和测试恢复云函数只能读取对应集合

### 目的

确认：

- `recoverData` 只读取正式集合。
- `recoverDataV2Test` 只读取 `test_` 测试集合。
- 客户端传入的集合前缀不能改变服务器选择。

### A. 在腾讯云控制台确认两个函数存在

1. 打开腾讯云控制台。
2. 进入“云开发 CloudBase”。
3. 进入本项目使用的环境。
4. 左侧点击“云函数”。
5. 在云函数列表确认存在 `recoverData`。
6. 再确认存在 `recoverDataV2Test`。
7. 分别打开两个函数，确认页面展示的函数名称与刚才选择的名称一致，函数状态正常。
8. 如果打开后只能看到内存、超时时间、运行环境、环境变量等参数，这是当前控制台的正常界面，不需要寻找“函数代码”或“在线编辑”。
9. 不要修改任何参数，不要点击部署、删除或保存。

服务器函数名与集合前缀的固定映射由本地自动化检查保证，不要求手工在腾讯云页面阅读源码。本次本地 `verify:cloud-env` 已经通过；正式部署时还需要保留部署版本和代码校验记录。

### B. 发布前只确认体验版调用测试恢复函数

1. 手机打开 1.0.2 体验版。
2. 进入“归藏”。
3. 确认页面显示“测试环境”。
4. 点击“清空缓存”。
5. 阅读弹窗后点击“确定”。
6. 等待出现“已恢复云端”。
7. 回到腾讯云控制台的云函数列表。
8. 打开 `recoverDataV2Test`，寻找“调用日志”“日志查询”或“监控日志”。不同控制台界面的名称可能不同；如果函数详情页没有日志入口，就返回 CloudBase 左侧菜单进入“日志”并按函数名筛选。
9. 刷新日志，确认刚才时间附近有一次成功调用。
10. 打开 `recoverData` 的调用日志。
11. 确认刚才体验版操作没有在 `recoverData` 中产生对应调用。
12. 到这里停止。不要用当前正式版 1.0.0 执行清空缓存。

`recoverData` 的正式客户端调用验证推迟到 1.0.2 正式发布后，按照场景 2 执行。发布前由自动化环境映射检查、云函数存在性和部署记录保证正式路由。

### 通过标准

- 云函数列表同时存在 `recoverData` 和 `recoverDataV2Test`，状态正常。
- 体验版只调用 `recoverDataV2Test`。
- 体验版操作没有调用 `recoverData`。
- 体验版恢复没有出现 `CLOUD_ERROR`、`NO_OPENID` 或超时。
- 体验版只显示测试数据。

### 失败时怎么办

出现以下任一情况立即停止：

- 找不到 `recoverData` 或 `recoverDataV2Test`。
- 任一函数状态异常。
- 体验版调用了 `recoverData`。
- 体验版出现正式数据。

不要重新部署其他云函数，不要提交审核。记录函数名、调用时间和错误截图，交给开发人员处理。

## 场景 2：1.0.2 正式版清缓存后完整恢复正式数据

### 执行时间

仅在 1.0.2 正式发布后执行。发布前只能用当前正式版确认正式云端数据仍存在，不能证明新客户端的正式环境行为。

当前正式版仍为 1.0.0 时，只允许正常查看已有数据，禁止点击“清空缓存”。

### 目的

确认普通正式用户清缓存后：

- 习惯仍存在。
- 全部正式历史打卡仍存在。
- 体验版测试数据不会出现。
- 首页和报表保持一致。

### 操作前记录

1. 使用账号 A 打开正式版。
2. 确认“归藏”页面没有“测试环境”标识。
3. 在首页截图当前习惯和今日打卡状态。
4. 进入“观心”，分别截图周报、月报。
5. 记录至少三个明确可核对的历史日期及其已打卡习惯。
6. 如果账号 A 是此前恢复的目标账号，还要记录：
   - 7 月 23 日：6 条 `checked`。
   - 7 月 24 日：6 条 `checked`。
   - 7 月 25 日：9 条 `checked`。
   - 7 月 26 日：无打卡。

### 清缓存与恢复

1. 保持手机网络正常。
2. 打开“归藏”。
3. 再次确认没有“测试环境”标识。
4. 点击“清空缓存”。
5. 阅读提示，点击“确定”。
6. 不要退出微信，不要切换小程序。
7. 等待加载结束。
8. 必须看到“已恢复云端”。
9. 如果看到“清理失败”“恢复失败”“有数据尚未同步”或“云端数据异常”，立即停止并截图。

### 恢复后核对

1. 回到首页，确认习惯数量、名称、排序和今日状态与操作前一致。
2. 进入“修习”，确认习惯及策略仍可查看。
3. 进入“观心”，核对操作前记录的三个历史日期。
4. 核对周报和月报没有突然归零。
5. 确认体验版新增的测试打卡没有出现在正式版。
6. 关闭小程序并重新打开一次，再重复第 1～5 步。

### 通过标准

- 显示“已恢复云端”。
- 正式历史完整恢复。
- 测试数据不出现。
- 重启后结果不变。
- 首页、修习和观心的数据一致。

## 场景 3：体验版只恢复测试数据，并且不影响正式数据

### 目的

确认同一微信账号在体验版和正式版之间切换时，两个环境的数据与缓存互不覆盖。

### 在体验版准备数据

1. 使用账号 B 扫描 1.0.2 体验版二维码。
2. 打开“归藏”，确认显示“测试环境”。
3. 进入“修习”。
4. 添加三个仅用于测试的习惯，例如“八段锦”“站桩”“揉腹”。
5. 回到首页，至少完成其中一项打卡。
6. 退出小程序，再重新打开体验版。
7. 确认三个习惯和打卡仍存在，证明它们已经同步到测试云端。

### 在体验版清缓存

1. 进入“归藏”。
2. 确认仍显示“测试环境”。
3. 点击“清空缓存 → 确定”。
4. 等待“已恢复云端”。
5. 回到首页，确认三个测试习惯和打卡均恢复。

### 切换到正式版核对隔离

1. 完全退出体验版。
2. 从微信最近使用的小程序中打开正式版，不要再次扫描体验二维码。
3. 进入“归藏”，确认没有“测试环境”标识。
4. 检查首页和观心：
   - 正式版原有数据仍存在。
   - 刚才体验版新增的测试打卡没有出现。
5. 如果当前正式版是 1.0.0，到这里停止。不要在 1.0.0 点击“清空缓存”。
6. 等 1.0.2 正式发布后，再按照场景 2 验证正式版清缓存恢复。

### 通过标准

- 体验版清缓存后只恢复测试数据。
- 当前正式版原有数据保持不变，体验版测试数据没有出现。
- 两边新增的打卡互不出现。
- 体验版清缓存没有改变正式版数据。

## 场景 4：核心功能真机回归

### 目的

确认缓存和同步底座修改没有影响普通使用体验。

先在 1.0.2 体验版执行完整一遍；1.0.2 正式发布后，再用账号 A 在正式版执行一遍。

### 操作步骤与预期结果

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 打开首页 | 页面正常打开，习惯列表和今日状态正常 |
| 2 | 选择一个未打卡习惯并打卡 | 页面立即显示已打卡，完成数增加 |
| 3 | 退出并重新打开小程序 | 刚才的打卡仍存在 |
| 4 | 取消刚才的打卡 | 页面恢复未打卡，完成数减少 |
| 5 | 再次退出并打开 | 取消结果仍存在 |
| 6 | 在“修习”添加一个新习惯 | 新习惯出现在列表和首页 |
| 7 | 修改新习惯的频次或时长 | 修改保存成功，重新进入后仍正确 |
| 8 | 删除刚才新增的测试习惯 | 习惯从当前列表移除，旧历史不导致报错 |
| 9 | 进入“观心”查看周报 | 页面正常，无空白、重复或异常归零 |
| 10 | 查看月报和年报 | 页面正常，未来日期不计入完成率 |
| 11 | 切换四个主页面 | 导航、页面刷新和数据展示正常 |
| 12 | 再执行一次小程序内清缓存 | 成功恢复后，首页、修习、观心结果一致 |

### 通过标准

- 所有步骤均没有白屏、卡死或持续加载。
- 打卡、取消、添加、编辑、删除都能保存。
- 重启和清缓存后，云端已确认的数据能够恢复。
- 报表没有重复计数或突然清零。

## 场景 5：断网或恢复失败时不得覆盖本地数据

### 目的

确认网络异常、分页中断或恢复失败时，原有本地数据仍被保留。

此场景先在体验版用账号 B 执行，不要首先用正式账号测试。

### 操作步骤

1. 打开 1.0.2 体验版。
2. 确认“归藏”显示“测试环境”。
3. 保证首页已有至少两个习惯和一条已打卡记录。
4. 截图首页和观心，作为失败前证据。
5. 打开手机飞行模式，或者同时关闭 Wi-Fi 和移动数据。
6. 回到小程序，进入“归藏”。
7. 点击“清空缓存 → 确定”。
8. 等待操作结束。
9. 预期看到“清理失败，请稍后重试”或“有数据尚未同步，请稍后重试”。
10. 回到首页和观心。
11. 确认第 3 步的数据仍然存在，没有被替换为空数据。
12. 完全关闭小程序并重新打开。
13. 在仍断网的情况下，确认本地数据仍能显示。
14. 关闭飞行模式，恢复网络。
15. 等待 10 秒。
16. 再次执行“归藏 → 清空缓存 → 确定”。
17. 这次应看到“已恢复云端”。
18. 核对原有测试数据完整恢复。

### 通过标准

- 断网恢复失败时，本地数据没有消失。
- 重启后本地数据仍存在。
- 网络恢复后可以重试并成功。
- 失败过程没有把空快照写入缓存。

### 重要提醒

不要通过微信设置或手机系统删除小程序数据。系统级删除会直接移除尚未同步的本地 pending，应用无法恢复从未上传到云端的数据。

## 场景 6：历史数据较多账号的恢复完整性和耗时

### 目的

确认历史记录较多时能够完成全部分页，不重复、不遗漏，并记录真实恢复耗时。

优先使用已知有约 292 条状态的账号 A。不要为了测试而向正式数据库批量制造假数据。

### A. 在腾讯云控制台只读记录云端数量

1. 打开腾讯云 CloudBase 控制台。
2. 进入“数据库 → 集合管理”。
3. 打开正式集合 `user_habits`。
4. 使用控制台的条件搜索，按账号 A 的 `_openid` 查询。
5. 记录该账号的习惯数量。
6. 打开 `habit_policy_versions`，按同一 `_openid` 查询并记录数量。
7. 打开 `daily_checkin_states`，按同一 `_openid` 查询并记录数量。
8. 不点击“添加记录”“导入”“编辑”或“删除”。
9. 分别截图三个集合的查询条件和数量。

如果控制台搜索框提示“按 key 条件符 value 的格式搜索记录”，它不是三个下拉选项。请点击搜索框，把下面整行条件直接粘贴进去，然后按回车：

```text
_openid == 目标账号 OpenID
```

例如：

```text
_openid == oCt9o12Rj50RtOaGiKKhwqf7QSMg
```

注意：

- 字段名是 `_openid`，前面有一个下划线。
- 等于条件使用两个英文等号 `==`。
- 这个旧版控制台的字符串 value 不加引号；双引号会被当作 value 本身的一部分，导致匹配不到。
- 不要输入 `key:`、`条件:`、`value:`，也不要加 JSON 大括号。
- 如果按回车没有反应，点击搜索框右侧的放大镜。
- 如果控制台提示语法错误，点击搜索框右侧的 `i` 信息图标并截图提示内容，不要尝试编辑或删除记录。

不要把 OpenID 发到公开群聊或截图公开发布。

### B. 记录真机恢复耗时

1. 确认手机网络稳定。
2. 打开对应环境的小程序：
   - 验证测试集合时打开体验版，并确认“测试环境”。
   - 1.0.2 发布后验证正式集合时打开正式版，并确认没有“测试环境”。
3. 在首页和观心截图恢复前的数据。
4. 打开手机秒表。
5. 回到小程序“归藏”。
6. 点击“清空缓存”。
7. 在点击弹窗“确定”的同时启动秒表。
8. 出现“已恢复云端”时停止秒表。
9. 记录总耗时。
10. 回到首页，核对习惯数量。
11. 进入观心，核对至少三个历史日期。
12. 对账号 A 额外核对 7 月 23、24、25、26 日。
13. 关闭并重新打开小程序，确认结果仍一致。
14. 到腾讯云控制台打开对应恢复函数的调用日志：
    - 正式版：`recoverData`。
    - 体验版：`recoverDataV2Test`。
15. 截图本次恢复期间的成功调用和耗时。

### 通过标准

- 恢复最终成功，没有分页超时。
- 本地恢复后的数量和云端记录可以解释一致。
- 抽查日期没有遗漏或重复。
- 多次分页使用同一完整快照，不出现“快照发生变化”。
- 函数日志没有 `RECOVERY_RESPONSE_TOO_LARGE`。

### 关于 5MB 极限

5MB 边界已经由自动化测试验证。不要在正式数据库中人工创建 5MB 数据进行测试。真实账号这里只验证正常数据量下的完整性和实际耗时。

## 四、统一停止条件

出现以下任一情况，停止审核或停止扩大发布：

- 正式版显示“测试环境”。
- 体验版没有显示“测试环境”。
- 体验版出现正式数据，或正式版出现测试数据。
- 清缓存后出现数据减少、报表归零或习惯丢失。
- 恢复失败后原有本地数据被清空。
- 云函数日志出现 `RECOVERY_RESPONSE_TOO_LARGE`、`CLOUD_ERROR`、`NO_OPENID`。
- 同一日期、同一 `userHabitId` 出现重复最终状态。
- 新版本的打卡、取消、习惯管理或报表与旧版本行为不一致。

发生问题时：

1. 不重复清缓存。
2. 不修改数据库。
3. 截图当前页面。
4. 记录账号、环境、时间、版本号和刚才的操作。
5. 保存对应云函数日志截图。
6. 交给开发人员排查。
